## 1) Redirection: do this first

Your shell already has command fields like `infile`, `outfile`, `append`, and `next` in minishell.h, so use those as the target state.

### Goal
Turn tokens like:

```bash
echo hello > out.txt
cat < in.txt
echo hi >> out.txt
```

into one `t_cmd` with:

- `cmd->outfile = "out.txt"`
- `cmd->append = 1` for `>>`
- `cmd->infile = "in.txt"`

### Recommended flow
- after tokenization, walk the token list
- when you see `<`, `>`, `>>`, set the command’s file fields
- skip the redirection operator and its file name from argv
- then build `argv` as only the command and its arguments

### Important rule
For redirection:
- open file in the child
- duplicate it to `STDIN_FILENO` or `STDOUT_FILENO` with `dup2`
- then `execve` or builtin execution

This is the pattern you want:

```c
fd = open(file, flags, 0644);
dup2(fd, STDOUT_FILENO);
close(fd);
```

For input redirection:

```c
fd = open(file, O_RDONLY);
dup2(fd, STDIN_FILENO);
close(fd);
```

## 3) Then add pipes

After single-command redirection works, move to pipelines.

### Minimal pipe logic
For a command chain like:

```bash
ls | grep .c | wc -l
```

do this:

- create `pipefd[2]` for each connection
- for each command:
  - fork
  - child:
    - if not first command: read from previous pipe
    - if not last command: write to next pipe
    - call `execve` or builtin
  - parent:
    - close the ends it used
    - keep the pipe for the next child
- wait for all children at the end

### Key rule
For pipelines, each child should have:
- stdin = previous pipe read end or STDIN
- stdout = next pipe write end or STDOUT

This is the classic shell pattern.
