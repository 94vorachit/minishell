## Step 1: fix and verify expansion

The relevant logic is in expand.c, and it is already called from main.c. The goal here is to make the expansion rules match Bash for the small set of cases below.

### What to verify

Use this exact checklist:

- `echo $USER`
- `echo "$USER"`
- `echo '$USER'` → should stay literal
- `echo hello$USER`
- `echo "$HOME/bin"`
- `echo $UNDEFINED` → empty string
- `echo $USER123` → expands `USER` and keeps `123`
- `echo $?` → last exit status
- `echo "$USER:$HOME"`

### The core rule to keep

Expansion should happen only when:
- we are not inside single quotes
- the current char is `$`
- the next char starts a valid variable name, or is `?`

### The bug-prone parts in expand.c

1. Variable name detection
- valid start: letter or `_`
- valid continuation: letter, digit, or `_`

This is already mostly implemented by:
- `is_var_start()`
- `is_var_char()`

But you must confirm:
- `$1` does not consume `1` as part of the name
- `$USER123` stops at `USER` and leaves `123` alone

2. Single quote rule
The logic must do this:
- if `'` and not in double quotes → toggle `in_single`
- if `$` appears while `in_single == 1` → do not expand

3. Empty/unset variable
If variable does not exist:
- result should just append nothing
- no crash
- no stale memory

4. `$?`
This must be handled before normal variable parsing:
- `word[*index + 1] == '?'` should expand to `g_data->status`

## Minimal fix pattern

Your function should follow this structure:

```c
else if (word[i] == '$' && !in_single)
{
    if (word[i + 1] == '?')
        ... expand status ...
    else if (is_var_start(word[i + 1]))
        ... parse name, lookup env, append value ...
    else
        ... keep literal '$' ...
}
```

The important detail is:
- if `$` is followed by something invalid, leave it as a literal `$`
- do not skip the next character incorrectly
